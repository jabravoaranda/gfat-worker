deployment

CPD deployment and update workflow

This page describes the intended operational deployment on a Linux service node in the CPD. The aim is to make updates boring: pull the repository, rebuild the image, restart services and run a small health check.

Deployment principles

  • The production node should run from a clean clone of the repository.
  • Secrets and local paths stay outside Git.
  • Updates should be limited to git pull, rebuild, restart and health checks.
  • RAW data is mounted read-only; generated products are mounted read-write.

The repository should contain code, Docker definitions and public documentation. The CPD node should contain environment files, mounted data paths and secrets.

Recommended server layout

/opt/gfat-worker/
  repo/                 git clone of gfat-worker
  env/.env.production   production environment file
  secrets/info_scc_user.yml

Initial installation

sudo mkdir -p /opt/gfat-worker/{env,secrets}
cd /opt/gfat-worker
git clone git@github.com:jabravoaranda/gfat-worker.git repo
cd repo
cp .env.example /opt/gfat-worker/env/.env.production

Edit /opt/gfat-worker/env/.env.production with the real CPD paths and service settings.

Keep this file out of the repository. It is specific to the machine where the service runs and may contain paths or operational settings that do not belong in Git.

Required environment

VariablePurpose
RAW_UGR_HOST_PATHHost path containing RAW input data.
PRODUCTS_UGR_HOST_PATHHost path where products are written.
SCC_CONFIG_HOST_PATHHost path to info_scc_user.yml.
API_PORTPublished FastAPI port.
FLOWER_PORTPublished Flower port when the ops profile is enabled.

Start production services

docker compose --env-file /opt/gfat-worker/env/.env.production \
  -f compose.prod.yml up -d --build api worker redis

After startup, check that all services are up and that the API responds. The exact URL depends on API_PORT. 

docker compose --env-file /opt/gfat-worker/env/.env.production -f compose.prod.yml ps
curl -fsS http://127.0.0.1:<API_PORT>/

Update after a repository change

cd /opt/gfat-worker/repo
git pull --ff-only
./scripts/deploy.sh /opt/gfat-worker/env/.env.production

The deployment script is meant to encode the normal update routine. If a manual command is needed repeatedly on the CPD node, add it to the script or document it here instead of relying on memory.

Operational commands

docker compose --env-file /opt/gfat-worker/env/.env.production -f compose.prod.yml ps
docker compose --env-file /opt/gfat-worker/env/.env.production -f compose.prod.yml logs -f api worker
docker compose --env-file /opt/gfat-worker/env/.env.production -f compose.prod.yml --profile ops up -d flower

Rollback

Use a known-good Git revision, rebuild and restart the services.

git checkout <known-good-commit>
./scripts/deploy.sh /opt/gfat-worker/env/.env.production

A rollback only works cleanly if operational files are outside Git and the product directories are mounted separately. That is why the production layout keeps repository, environment and secrets in different paths.
