gfat-worker

Run, schedule and inspect GFAT processing tasks

gfat-worker is an operational Docker service for running Python processing tasks through FastAPI, Celery and Redis. It currently runs ALHAMBRA LIDAR workflows with atmolidarpy, and it is structured so new task modules can be added for packages such as mrrpropy or dcrpy.

Getting started Implement a task

Why this service exists

GFAT processing is not only a set of Python scripts. In operation it needs a repeatable way to receive a request, run the right scientific code in the right environment, keep track of the execution, and write products to known locations. This repository packages that execution layer.

  • Exposes a generic API for queuing registered Celery tasks.
  • Runs scheduled operational jobs through Celery Beat.
  • Mounts RAW data read-only and writes products to a controlled path.
  • Builds a reproducible worker image with scientific dependencies pinned.
  • Supports extension through independent task modules.

Read this in order

  • Getting started: install the local tools, run the fast tests and start the API.
  • Architecture: understand which container owns each responsibility.
  • API usage: submit a task, read its state and interpret results.
  • Adding tasks: add a module for mrrpropy, dcrpy or another package.
  • Deployment: run and update the service on the CPD node.

Current LIDAR backend

The runtime dependency is atmolidarpy==0.1.0. Python code imports it as lidarpy. The worker no longer depends on gfatpy at runtime.

Operational model

Production uses compose.prod.yml with separate API, worker and Redis services. Secrets and local paths live outside Git in .env.production and info_scc_user.yml.

Open deployment guide

What is not in Git

Real RAW files, generated products, SCC credentials and local server configuration are intentionally excluded from the repository. The code and Docker definitions are versioned; operational data and secrets are mounted at runtime.
