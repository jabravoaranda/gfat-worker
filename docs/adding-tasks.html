adding tasks

Implement new processing modules

Use this workflow for packages such as mrrpropy, dcrpy, or any other Python processing library.

Implementation checklist

  1. Add the runtime dependency to worker/requirements.txt.
  2. Create a task module under worker/tasks/.
  3. Register the module in worker/app.py.
  4. Add tests for imports and task registration.
  5. Document inputs, outputs, mounts and environment variables.

1. Add the dependency

# worker/requirements.txt
mrrpropy==0.1.0
dcrpy==0.1.0

Pin production versions. Do not install packages dynamically every time the container starts.

2. Create the task module

# worker/tasks/mrr.py
from celery import shared_task


@shared_task
def mrr_backend_status():
    import mrrpropy

    return {
        "backend": "mrrpropy",
        "module": mrrpropy.__name__,
    }

The public Celery task name is:

tasks.mrr.mrr_backend_status

3. Register the module

# worker/app.py
app.autodiscover_tasks([
    "tasks.lidar",
    "tasks.misc",
    "tasks.mrr",
], force=True)

4. Prefer backend adapters for optional packages

# worker/mrr_backend.py
try:
    import mrrpropy
    MRR_BACKEND = "mrrpropy"
except ImportError:
    MRR_BACKEND = "missing"

    def _missing(*args, **kwargs):
        raise RuntimeError("MRR processing requires the 'mrrpropy' distribution.")

5. Add tests

# tests/test_registered_tasks.py
expected_tasks = {
    "tasks.misc.test_sum",
    "tasks.mrr.mrr_backend_status",
}

Run:

uv run pytest -q

6. Return structured results

return {
    "status": "ok",
    "message": "MRR product created.",
    "created_files": [output_path.name],
    "skipped_files": [],
    "errors": [],
}
Avoid returning only free-form strings for new tasks. Structured results are easier to inspect through the API and safer for future dashboards.

Operational documentation per task

Each new module should document:

  • required package and version
  • required mounts and environment variables
  • input file naming convention
  • output directory convention
  • whether it contacts external services
  • example JSON payload for /task_queue
